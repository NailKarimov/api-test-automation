Bruno: коллекция запросов, которая живёт в git

Bruno: an API collection that lives in git

Клиент для API вроде Postman, но коллекция — это папка текстовых файлов .bru: её смотрят в pull request как код, она не требует аккаунта и запускается в CI той же командой. Коллекция бьёт в ту же приватную Petstore в Docker, что и тесты на Playwright.

An API client like Postman, but a collection is a folder of plain-text .bru files: reviewed in pull requests like code, no account needed, and run in CI with the same command. It targets the same private Petstore in Docker as the Playwright suite.

Коллекция изнутри

Inside the collection

Выберите запрос — справа его файл .bru и что делает каждый блок. Запросы первой папки связаны переменной petId: созданного питомца читают, ищут, меняют и удаляют следующие запросы.

Pick a request to see its .bru file and what each block does. Requests in the first folder are chained by the petId variable: the pet created first is read, searched for, updated and deleted by the next ones.

Ловушка: Bruno не хотел отправлять битый JSON
A trap: Bruno would not send broken JSON

      
Негативный тест «битый JSON → 400» сначала падал. Сервер получал не битый, а вполне валидный JSON — строку. Библиотека axios под Bruno перекодирует строку, которая не парсится, в JSON-строку, если в Content-Type есть application/json. Переключите заголовок.

      
The negative test "broken JSON → 400" failed at first. The server got valid JSON, a string, not the broken body. The axios library under Bruno re-encodes a string that does not parse into a JSON string whenever the Content-Type contains application/json. Switch the header.
