GraphQL: один адрес, клиент сам выбирает поля

GraphQL: one endpoint, the client picks the fields

В REST у каждого ресурса свой адрес, и сервер решает, что вернуть. В GraphQL есть один /graphql, клиент присылает запрос-документ и получает ровно те поля, которые попросил. Для тестировщика это меняет почти всё: коды ответа, ошибки, безопасность. Тесты гоняются против публичного Rick and Morty API — у него есть REST-двойник с теми же данными.

In REST every resource has its own URL and the server decides what to return. GraphQL has one /graphql: the client sends a query document and gets exactly the fields it asked for. For a tester that changes almost everything: status codes, errors, security. The tests run against the public Rick and Morty API, which has a REST twin with the same data.

      Главная находка про устройствоThe main finding about the setup
      
Запрос проходит четыре слоя, и отвечать может любой
A request passes four layers, and any of them can answer

      
По исходникам 2022 года ждали один Apollo Server. Тесты показали, что перед ним стоят Cloudflare и Stellate — GraphQL-кэш. Выберите запрос и посмотрите, какой слой его остановил.

      
The 2022 source suggested a single Apollo Server. The tests showed Cloudflare and Stellate (a GraphQL cache) in front of it. Pick a request and see which layer stopped it.

    

    

    

  


  

    

      Граничные значенияBoundary values
      
Лимит глубины: 4 можно, 5 нельзя
Depth limit: 4 is allowed, 5 is not

      
Глубокий запрос character → episode → characters → episode → … размножает нагрузку на каждом уровне. Тест строит запрос нужной глубины и проверяет обе стороны границы.

      
A deep query character → episode → characters → episode → … multiplies the load at every level. The test builds a query of a given depth and checks both sides of the boundary.

      Дрейф схемы — как oasdiff, только для GraphQLSchema drift: oasdiff for GraphQL
      
GraphQL Inspector: живая схема против утверждённой
GraphQL Inspector: live schema vs approved

      
Тест получает схему через introspection и сравнивает её с contracts/rickandmorty/schema.graphql из исходников. Ломающих изменений нет. 11 безопасных — это служебные вещи, которые Apollo Server 2 добавляет сам: директива @cacheControl и скаляр Upload.

      
The test fetches the schema through introspection and compares it with contracts/rickandmorty/schema.graphql from the source. No breaking changes. The 11 safe ones are what Apollo Server 2 adds by itself: the @cacheControl directive and the Upload scalar.
